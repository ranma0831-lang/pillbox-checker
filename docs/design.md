## 1. 목적과 사용자

| 항목 | 내용 |
|---|---|
| 목적 | 포트폴리오 작품 |
| 현장 사용자 | 혼자 지내며 하루 1회 약을 먹는 어르신. 상자의 LCD·LED·버튼만 사용 |
| 원격 사용자 (주 대상) | 떨어져 사는 가족. 휴대폰 브라우저로 확인 |
| 해결할 상황 | 정해진 시각에 약을 먹었는지 가족이 바로 알고, 놓쳤으면 대응한다 |
| 성공 기준 | 가족이 첫 화면을 3초 보고 "오늘 드셨나"에 정확히 답한다. 놓친 날은 알림으로 안다 |
| 범위 밖 | 인터넷 원격 접속, 휴대폰 푸시 알림, 여러 약·여러 회 복용, 계정 |

## 2. 하드웨어

SZH-EK013 고급키트 부품만 사용합니다. UNO 호환 R3 1대, 빵판 1개, USB 전원.

| UNO 핀 | 부품 | 빵판 | 비고 |
|---|---|---|---|
| D8 | 빨강 LED + 1kΩ | 저항 C4–C7, LED E7(+)·E8(−) | 복용 알림 |
| D9 | 초록 LED + 1kΩ | 저항 C10–C13, LED E13(+)·E14(−) | 오늘 확인됨 |
| D2 | 택트 스위치 | E16·E18·F16·F18 | INPUT_PULLUP, 반대편 J16→GND |
| D3 | 볼 기울기 스위치 | E20·E22 | INPUT_PULLUP, 뚜껑 안쪽에 암–수 선으로 부착 |
| A4/A5 | LCD1602 I2C | J4 GND·J6 VCC·J8 SDA·J10 SCL | |
| 5V/GND | 분배 | 1번 줄 5V, 2번 줄 GND, E1–F1·J2–A2 점퍼 | |

- 선은 총 16개입니다. 한 선씩 연결하는 순서는 배선도 페이지에 있습니다.
- FND는 쓰지 않습니다. 숫자 한 자리에 저항 8개가 필요해 빵판이 부족하고, LCD로 같은 정보를 보여 줄 수 있기 때문입니다.
- RTC는 조건 확인이 필요한 부품이라 쓰지 않습니다. 시각은 모두 PC 기준입니다.
- 연결하기 전에 USB를 분리하고, 실물 핀 표시를 그림과 대조합니다.

## 3. 구조

```
[UNO] ⇄ USB 115200 ⇄ [bridge.py: 시리얼·판정·기록·웹] ⇄ 같은 Wi‑Fi ⇄ [가족 휴대폰 브라우저]
                         ├ settings.json
                         └ records.jsonl (90일)
```

- PC 프로그램은 Python 하나(`bridge.py`)입니다. 의존성은 `pyserial`뿐이고, 웹 서버는 표준 라이브러리 `http.server`(ThreadingHTTPServer)를 씁니다.
- 휴대폰은 2초마다 `/api/state`를 조회합니다. 화면이 잠겼다 깨어나도 다음 조회에서 회복됩니다.
- **판정은 PC 프로그램 한 곳에서만** 합니다. 그래서 휴대폰이 꺼져 있어도 상자 알림이 동작합니다.

파일 구성:
```
pillbox/
  firmware/pillbox/pillbox.ino
  pc/bridge.py
  pc/judge.py          # 순수 판정 함수 (테스트 대상)
  pc/test_judge.py
  web/index.html  web/style.css  web/app.js
  README.md
```

## 4. 보드 계약

규칙은 수업 P01과 같습니다. 115200, LF 줄 끝, `요청번호 명령 인수` 형식이고 요청번호는 1~65535입니다. 시작할 때 LED는 모두 꺼져 있고, D0·D1은 비워 둡니다. 긴 delay는 쓰지 않습니다.

**보드 → PC**
```json
{"v":1,"type":"state","profile":"PILL","request":0,"ms":5000,"lid_open":false,"button_pressed":false,"remind":0,"done":0,"msg":0,"lcd_ready":true}
{"v":1,"type":"event","event":"lid_open","ms":5210}
{"v":1,"type":"event","event":"lid_close","ms":9100}
{"v":1,"type":"event","event":"press","ms":7400}
{"v":1,"type":"ack","request":12,"applied":true}
{"v":1,"type":"error","request":13,"code":"bad_command"}
```
- `state`는 1초마다 보냅니다. STATUS에 대한 응답에는 요청번호가 들어갑니다.
- `lid_open`/`lid_close`는 기울기 입력이 50ms 동안 같은 값으로 안정됐을 때만 보냅니다.
- `press`는 버튼을 눌렀다 뗄 때 1번 보냅니다. 인정 여부는 PC가 판정합니다.
- `ms`는 전원을 켠 뒤 지난 시간입니다. 실제 시각은 PC가 받은 순간에 붙입니다.

**PC → 보드**
| 명령 | 동작 |
|---|---|
| `REMIND 0/1` | 빨강 LED 0.5초 간격 깜빡임 끄기/켜기 (PC는 복용 시각 +3분부터 1을 보냄) |
| `DONE 0/1` | 오늘 확인 여부 (초록 LED는 이 값이 아니라 확인 버튼 뒤 10초만 켜짐) |
| `WINDOW 0/1` | 지금이 확인 인정 구간인지 알려 줌. 상자에서 바로 보여 줄 반응을 정하는 데 씀 |
| `MSG 0~4` | LCD 화면: 0 `NEXT DOSE`/`AT 08:00` · 1 `MEDICINE TIME!`/`DOSE 08:00 NOW` · 2 `DONE TODAY  :)`/`TAKEN AT 08:12`(시각 전엔 `WELL DONE`) · 3 `PC LOST`/`CHECK THE PC` · 4 `OVERDUE   08:00`/`PRESS BUTTON` |
| `DOSE hhmm` · `TAKEN hhmm` | LCD에 쓸 복용 시각·확인 시각 (`TAKEN -1`은 아직 없음) |
| `STOP` | 모든 LED 끄기, MSG 0 |
| `STATUS` · `PING` | 즉시 상태 / 응답 확인 |

**보드 혼자 하는 동작**
- 버튼을 눌렀을 때 `WINDOW 1`이면 빨강 깜빡임을 바로 끄고, 초록 LED를 **10초** 켜고, LCD를 완료 화면으로 바꿉니다. `WINDOW 0`이면 초록을 짧게 두 번만 깜빡입니다(인정 전 누름). (2026-10-29 사용자 요청으로 변경)
- 10초 동안 아무 명령도 오지 않으면 `MSG 3`을 띄우고 REMIND 깜빡임을 멈춥니다. PC는 3초마다 PING을 보냅니다.
- LCD는 영문 16자 이내로만 씁니다. LCD1602는 한글을 표시하지 못합니다.

## 5. 판정 규칙 (`judge.py`)

복용 시각을 D(기본 08:00), 유예를 30분이라고 합니다.

| 상태 | 조건 | 보드 출력 |
|---|---|---|
| `before` 인정 전 | 지금 < D−2시간 | MSG 0, WINDOW 0 |
| `window` 곧 드실 시간 | D−2시간 ≤ 지금 < D | MSG 0, WINDOW 1 |
| `due` 드실 시간 | D ≤ 지금 < D+30분 | MSG 1, WINDOW 1 |
| `caution` 주의 | D+30분 ≤ 지금 < D+60분 | MSG 1, REMIND 1 |
| `warning` 경고 | 지금 ≥ D+60분 | MSG 1, REMIND 1 |
| `done` 확인됨 | 그날 D−2시간 이후 첫 `press` ≤ D+30분 | DONE 1, REMIND 0, MSG 2 |
| `late` 늦게 확인 | 첫 인정 `press` > D+30분 | DONE 1, REMIND 0, MSG 2 |
| `missed` 놓침 | 지난 날, 인정 `press` 없음 | — |
| `none` 기록 없음 | 지난 날, 그날 PC 기록이 없음 | — |
| `unknown` 알 수 없음 | 오늘, 보드 수신이 1분 넘게 없음 | — |

- D−2시간 전에 누른 `press`는 `early_press`로 기록만 하고 판정에 쓰지 않습니다.
- 뚜껑 열림은 기록과 화면 표시에만 쓰고 판정에는 쓰지 않습니다. 뚜껑을 연 것이 약을 먹었다는 뜻은 아니기 때문입니다.
- 자정이 되면 `before`로 돌아가고 DONE 0을 보냅니다.
- 판정 함수는 시각을 인자로 받는 순수 함수로 만듭니다. 시안의 `judge()`와 같은 규칙입니다.

## 6. PC 프로그램 (`bridge.py`)

**시리얼**
- 포트는 실행 인자로 지정합니다(`--port COM5`). 연결 후 2초를 기다리고 STATUS를 보내 `profile=PILL`인지 확인합니다.
- 포트가 끊기면 3초마다 다시 연결합니다. "포트 사용 중"과 "포트 없음"을 구별해 표시합니다.
- 출력 명령은 판정 결과가 바뀔 때만 보냅니다. ACK를 2초 기다리고, 오지 않으면 "적용 미확인"으로 기록하며 자동 재전송은 하지 않습니다.
- 다시 연결되면 현재 판정에 맞는 출력을 한 번 보냅니다.

**기록**
- `records.jsonl`에 한 줄씩 씁니다: `{"t":"2026-10-29T08:12:03","e":"press|early_press|lid_open|lid_close|ack|connect|disconnect|setting|unconfirmed"}`
- 시작할 때 90일이 지난 줄을 정리합니다. 깨진 줄은 건너뛰고 경고만 출력합니다.
- `settings.json`: `{"dose_time":"08:00","grace_min":30}`

**API** (모두 접속 코드 `k`가 필요하며, 없거나 틀리면 403)
| 경로 | 내용 |
|---|---|
| `GET /` | `web/` 정적 파일 |
| `GET /api/state` | 오늘 판정, 확인 시각, 오늘 사건, 알림 단계, 가족 확인 여부, 보드 연결과 마지막 수신 후 초, 서버 시각, 데모 여부 |
| `GET /api/history?days=35` | 날짜별 판정, 확인 시각, 사건 목록 |
| `POST /api/settings` | `{"dose_time":"HH:MM"}`. 형식 오류면 400과 이유 |
| `POST /api/ack` | 가족 확인 기록 (오늘, 경고·주의 단계일 때) |

**접속 코드:** 실행할 때마다 무작위 4자리 이상을 만들고, 콘솔에 `http://<PC IP>:8000/?k=XXXX`를 출력합니다. 같은 Wi‑Fi 안의 다른 사람이 건강 정보를 보지 못하게 하려는 것입니다.

**`--demo`:** 보드 없이 연습 사건을 만들어 냅니다. 이때 API 응답에 `demo:true`가 들어가고, 화면에는 "연습 데이터" 띠가 항상 표시됩니다.

## 7. 휴대폰 화면 (`web/`)

순서와 모양은 시안을 따릅니다.

1. 연결 띠: 연결 상태와 "N초 전 수신". 상자 끊김과 PC 프로그램 끊김은 다른 문구로 표시
2. 알림 띠: 주의는 노랑, 경고는 빨강과 소리·진동·탭 제목 "(!)", 알 수 없음은 회색. "확인했어요"(가족 확인)와 "소리 끄기" 버튼
3. 상태 카드: 아이콘 + 문장 + 색. 복용 시각, 인정 시작, 뚜껑 열림 횟수
4. 타임라인: 04–24시. 인정 구간, 유예, 복용 시각, 지금 위치, ▲ 뚜껑, ✓ 확인, ○ 인정 전 누름, ◆ 가족 확인
5. 월 달력: ✓ ! ✕ · 기호와 확인 시각, 뚜껑 열림 횟수. 날짜를 고르면 4와 6이 그날로 바뀜
6. 최근 14일 그래프와 요약 숫자 (최근 7일 확인 일수, 평균 확인 시각, 복용 시각 대비 차이)
7. 기록 표: 3~6의 내용을 모두 글로 제공
8. 설정: 복용 시각, 알림 소리 켜기, 자동 갱신 멈춤

**알림의 한계:** 같은 Wi‑Fi에서 `http://`로 접속하면 브라우저가 보안 연결로 보지 않아 푸시 알림을 쓸 수 없습니다. 알림은 페이지가 열려 있을 때만 동작합니다. 소리는 "알림 소리 켜기"를 한 번 누른 뒤에만 납니다.

**접근성 구현 기준**
| 기준 | 구현 |
|---|---|
| WCAG 1.1.1 | SVG에 title을 넣고, 같은 내용을 기록 표로도 제공 |
| WCAG 1.4.1 | 모든 상태에 기호와 문장을 함께 표시 |
| WCAG 1.4.2 | 경고 소리는 "확인했어요"·"소리 끄기"로 멈춤 |
| WCAG 1.4.3 / 1.4.11 | 글자 4.5:1, 그래프 표시와 테두리 3:1 이상. 라이트·다크 모두 |
| WCAG 2.1.1 / 2.4.7 | 모든 조작을 키보드로. 달력은 화살표 키, 초점 테두리 3px |
| WCAG 2.2.2 | 자동 갱신 멈춤 버튼 |
| WCAG 2.4.11 | 고정 요소를 두지 않아 초점이 가려지지 않음 |
| WCAG 2.5.8 | 버튼 최소 44px |
| WCAG 3.3.1 | 설정 입력 오류를 입력란 옆에 글로 표시 |
| WCAG 4.1.3 | 연결·상태 변화는 `role="status"`, 경고만 `role="alert"`. 매초 바뀌는 수신 초는 알리지 않음 |
| ISO 9241-110 | 과업 적합성(첫 화면 판단 1개), 자기 설명성(기호 범례), 기대 일치(보냄·적용·미확인 구분), 오류 내성(끊김·null·0 구별) |
| ISO 9241-11 | 사용 맥락(현장 vs 원격)을 사용자 정의 근거로 기록, 3초 과업 테스트 |

## 9. 테스트

1. **자동 테스트** (`pc/test_judge.py`, 보드 없이)
   - 판정 경계: 05:59 미인정, 06:00 인정, 08:30 done, 08:31 late, 08:29/08:30/08:59/09:00 단계 전환, 자정 초기화, 지난 날 missed/none, 수신 1분 초과 unknown
   - 기록: 90일 정리, 깨진 줄 건너뛰기, 설정 형식 검사
   - API: 접속 코드 403, `/api/state` 키 구조
2. **펌웨어** (시리얼 모니터): 뚜껑 방향과 흔들림 1회, 길게 눌러도 press 1회, 명령별 ACK와 error, 10초 뒤 PC LOST, WINDOW 0일 때 두 번 깜빡임
3. **통합** (실물 + 휴대폰): 버튼을 누르면 2초 안에 "확인됨", 복용 시각을 지금+1분으로 두고 주의·경고와 소리·가족 확인 확인, USB 뽑기와 PC 프로그램 끄기의 문구 구별
4. **표준 검사:** 색 쌍별 대비 수치, 키보드만으로 조작, 버튼 크기 측정, 흑백 캡처, TalkBack 또는 NVDA 낭독, 가족 역할 1명에게 3초 과업 테스트
